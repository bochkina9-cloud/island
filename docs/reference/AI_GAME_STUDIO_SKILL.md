## Цель
Доводить ИИ-создание игры до уровня «не слоп»: по фазам, с проверкой каждой
механики и каждой генерации, а не одним промптом.

## Пайплайн — 10 фаз, по одной за раз
Идея → Стиль → Движок/окружение → Ассеты → Механики (гимы) → Уровни →
Сборка → Полировка → Релиз.

Фаза N+1 НЕ начинается, пока у фазы N нет проверенного результата:
1) запускается; 2) бот-проходчик зелёный или скриншот без ошибок;
3) строка решения в REVIEW.md.

## Ключевые приёмы

1. **Гимы механик.** Каждая механика (движение, голод, крафт, костёр, бой)
   отрабатывает в отдельной мини-сцене `src/gyms/<имя>.ts` ДО интеграции
   в игру.
2. **Бот-проходчик.** Headless-скрипт (`tests/route.mjs`) гоняет сценарий
   «идти → собрать → скрафтить» и логирует, где герой застрял/погиб.
3. **Единый референс персонажа.** Сначала ОДИН утверждённый спрайт героя;
   все позы и анимации — только производные от него.
4. **Спрайты на #FF00FF.** Генерировать на сплошном пурпурном фоне со
   строгим ракурсом (side-view для платформера, top-down под углом для 2.5D);
   фон вырезается кодом.
5. **«Локация = картина».** Геометрия и коллизии строятся первыми (json-разметка),
   финальный арт кладётся поверх ЦЕЛИКОМ; обязательна overlay-сверка арта
   с разметкой — сдвиги = перерисовать.
6. **Журнал решений REVIEW.md** — дата + решение, чтобы откатывать.
7. **Скриншот после каждой фазы** и сверка с утверждённым концептом.
8. **Оркестратор + помощники.** Сильная модель ведёт проект и ПРОВЕРЯЕТ
   (в т.ч. зрением: читает разметку, сверяет стиль); слабые собирают черновики.

## Как НЕ делать (антипаттерны из видео)

- Генерить игру одним промптом → гарантированный «слоп».
- Класть сгенерированную картинку ЦЕЛИКОМ как игровой слой — слои
  собираются из отдельных спрайтов + кода.
- Спрайты без строгого ракурса и фона #FF00FF → потом не вырезать.
- Несколько разных референсов героя → герой «плавает» между кадрами.
- Собирать уровень из кусков окружения → швы, объекты висят в воздухе;
  зал/локацию рисовать одной картиной поверх готовой геометрии.
- Доверять генерации на слово: «мост в провал», сдвинутые ступеньки,
  хождение по воздуху — ловится ТОЛЬКО overlay-сверкой разметки и арта.
- Godot для браузерной 2D-игры: тяжёлая веб-сборка, нет пост-эффектов.
- Механики без гимов: «инерция» и «распрыжка», которые игрок не чувствует
  и не понимает, как использовать.
- Меню «на сдачу» в самом конце — делать до полировки.
- Босс с 5-6 рандомными атаками — непредсказуемость = фрустрация;
  дерганая анимация (модель ушла, огонь остался на месте) — перерисовка кадров.
- Слабая модель на 2D-геометрии уровней: непонятно куда прыгать, цепи
  обрываются, платформы заезжают внутрь уровня — геометрию отдавать
  сильной модели или строить кодом.

## Признак готовности фазы
Запускается + бот/скриншот чистый + запись в REVIEW.md. Только после
этого — следующая фаза.
